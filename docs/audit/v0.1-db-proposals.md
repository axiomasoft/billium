# 0.1 Database Audit: Open Proposals

This page lists database findings from the 0.1.0 review that were measured but not implemented, because
each one needs a design decision, changes a tested invariant, or touches a public API. The changes that were
made are listed in [performance](../operations/performance.md#round-trips-and-write-amplification-010) and in
the [changelog](../../CHANGELOG.md).

Measurements come from PostgreSQL 16.16 over local TCP, with `pg_stat_statements` (`track = all`) over the
full PostgreSQL test suite (1675 parallel + 38 serial tests), unless a row says otherwise.

| # | Area | Finding | Evidence | Proposal | Why not in 0.1 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 1 | Runner | `Operation::isOpen()` runs `SELECT pg_current_xact_id()` on every capability check, about 39 times per root operation. | 822k calls in the suite; about 30 µs each with `DISABLE_PREPARES`, so about 1.2 ms per root operation. | Cache the xid per root and re-check only when the PDO transaction level or object changes, or compare `PDO::inTransaction()` plus a per-root token. | The D60 test `test_replacing_the_root_transaction_on_the_same_pdo_invalidates_every_capability` requires that replacing the transaction on the same PDO invalidates capabilities; any cache must keep that guarantee. Needs a design review. |
| 2 | Lock plan | `LockSet` locks `billium_module_state` `FOR SHARE` and the module then reads the same row again. | One extra statement per guarded module per root. | Let `LockSet` select the columns the module needs in its `SELECT ... FOR SHARE` and return them. | Changes the `LockSet` contract used by every module. |
| 3 | Idempotency | `DatabaseIdempotencyStore` wraps the receipt lock in `SET LOCAL lock_timeout = '<n>ms'` and `SET LOCAL lock_timeout = 0`: two extra statements per idempotent command, and the reset sets 0 instead of the previous value. | Two statements per idempotent command. | Send both through `set_config('lock_timeout', ..., true)` in the lock statement itself, and restore the previous value instead of 0. | Touches the in-flight conflict semantics that the idempotency tests pin; needs its own review. `DatabaseInstallation` seal has the same pattern. |
| 4 | Execution | The execution module reads the same operation row repeatedly within a root. | 24k and 15k calls of the two hottest operation reads in the suite. | Pass the locked row through the worker instead of re-reading it. | Spread over several workers; needs a refactor of the execution internals. |
| 5 | Ledger | `billium_ledger_json_safe()` validates JSON with a regular expression on every write. | 807k calls in the suite, about 7 µs per row. Inlining the check gave no gain. | Validate once at the PHP boundary and keep the database check only as a constraint on the stored column. | It is a defence-in-depth check; removing it is a security decision. |
| 6 | Feed | `billium_feed_command_lease` rows are inserted and updated but never deleted. | No `DELETE` on the table in the code; the runtime role has only `SELECT, INSERT, UPDATE`. | Add pruning of released leases to `OutboxPruner` with a retention window. | Needs a retention decision and a grant change. |
| 7 | Metrics | `billium:server:metrics` scans `billium_inbox_message` once by `status`; there is no index on the parked statuses outside `parked_dependency`. | 35 ms at 300k rows after the 0.1 change. | A partial index `WHERE status IN ('parked_gap', 'held_recovery')` if metrics are scraped often on large inboxes. | Only worth it with a production scrape interval and inbox size. |
| 8 | Runner | The runner retries `40001` and `40P01` immediately, without backoff. | No sleep between attempts in `DatabaseOperationRunner`. | Add a short jittered backoff (for example 5–50 ms) between deadlock retries. | Changes the deadline budget of a root operation; needs a decision on the interaction with `billium.runner.root_deadline_ms`. |
| 9 | Bench | `scripts/bench/billing.py` reports `outbox.feed_scope_page` as failing: on its tiny dataset the planner uses `billium_outbox_event_cursor` instead of the scope index. | Fails on main as well; the script is not part of CI. | Seed the bench with enough rows (or `ANALYZE` plus planner stats) so the plan matches production, or assert on the index set only. | Bench tooling, not product code. |
| 10 | Connection | `Pdo\Pgsql::ATTR_DISABLE_PREPARES` halves query latency but Billium cannot set it on the host connection. | 60.7 → 30.7 µs/query. | A doctor/readiness warning when the Billium connection uses native prepares. | Adds a new doctor check; product decision. |
| 11 | Unused API | Public (`#[Api]`) types with no reference outside their own file and `php-api.json`: `Rating\Data\Tax\TaxLineInput`, `Rating\Data\Tax\TaxResult`, `Rating\Enums\BasisKind`, `Schedule\Enums\ScheduleState`, `Usage\Data\EffectiveFact`. `Usage\Internal\UsageQueries` and `Rating\Internal\Adapters\WirePriceVersionMapper` are used only by tests. | Repository-wide reference scan. | Remove them, or wire them where the design intended. | Removing `#[Api]` types is an API change; decide before the 0.1.0 tag. |
