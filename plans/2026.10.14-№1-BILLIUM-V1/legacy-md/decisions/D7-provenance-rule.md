# D7 — Правило происхождения: без утверждений без источника

**Actor:** designer/frontier/high (claude-opus-5-5)
**Evidence:** RAG:— (repo-grounded: требование владельца в design-сессии 2026-10-14 «при детализации не должно быть отсебятины»; `brief/00-owner-message.md` §1, §6)

## Solution

Каждое нормативное утверждение в артефактах P1 и в детализации P2+ несёт ссылку на происхождение.
Допустимые ссылки — ID с одним владельцем:

| Тип | ID | Где определён |
|:--|:--|:--|
| требование / инвариант | `REQ-<AREA>-NN`, `INV-NN` | `docs/requirements.md` |
| документ корпуса | `SRC-NNN` | `research/P1-corpus.md` |
| единица аудита | `AUD-NNN`, `C-NN`, `V3-NN`, `AC-NN`, `G-NN`, `R-NN`, `FS-NN`, `E-NN`, `L-NN`, `Q-NN` | `research/P1-audit-inventory.md` |
| утверждение матрицы | `CL-NN` | `knowledge/audit-matrix.md` |
| первичный факт | `DR0N-NN` | `knowledge/research/DR-0N*.md` |
| практика | `M-NN` | `knowledge/methods.json` |
| решение | `D#` | `decisions/` |

Правила:
1. Факт без ссылки не пишется. Вывод исполнителя — это `D#` с альтернативами или строка с меткой
   `hypothesis`, и у неё тоже есть ссылки на основания.
2. Ссылка обязана разрешаться: ID существует у своего владельца. Checker проверяет это для всех
   таблиц, где требуется основание.
3. Бизнес-факты (продавцы, цены, налоги, PSP, валюты) не выводятся, а становятся вопросом владельцу.
4. Детализация P2–P10: scope item-а берётся только из `knowledge/roadmap-proposal.md`, D#,
   REQ/INV и каталога приёмки. `Why` каждого item ссылается на них. Новый scope вводится только
   новой D-записью с основаниями.
5. P1.9 выборочно проверяет утверждения на происхождение. Утверждение без разрешимой ссылки —
   finding уровня major.

## Why

- Альтернатива A — общее правило «опираться на источники» без ID. Отклонена: такое правило не
  проверяется, и синтез модели неотличим от факта.
- Альтернатива B — сноски-URL/пути у каждой фразы. Отклонена: тяжело читать, ссылку на путь нельзя
  проверить на полноту. ID с владельцем проверяется checker-ом.

## Consequences

`check-p1.py` проверяет разрешимость ссылок в колонках «Источник», «Основание», «Требования»,
«Ссылки», «Решения» и в `**Evidence:**` D-записей P1.6+. Архитектурные D-записи P1.6 начинаются с D8.
