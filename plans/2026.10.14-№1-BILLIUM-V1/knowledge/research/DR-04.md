## Предложение fixtures (не выполнено)

Language-neutral вектора для P1.7; ожидания выведены из DR04-11…13 и REQ-ACC-13, conformance не запускался (DR04-24).

| Вектор | Вход | Ожидание |
|:--|:--|:--|
| scale RUB/JPY/KWD | `"1.00" RUB`, `"1" JPY`, `"1.000" KWD` | принимаются; `"1.0" JPY`, `"1.0000" KWD` — ошибка scale |
| currency mismatch | `add("1.00" RUB, "1.00" USD)` | ошибка mismatch, не конвертация |
| int64 границы | minor `"9223372036854775807"`, `"-9223372036854775808"` | round trip; +1 к максимуму — overflow, не wrap |
| > 2^53 | minor `"9007199254740993"` | round trip без потери (строка, DR04-12, DR04-13) |
| allocation остаток | `"1.00" USD` по `[2, 3, 1]`, largest remainder | `[0.33, 0.50, 0.17]` (DR04-06) |
| allocation отрицательная | `"-1.00" USD` по `[1, 1, 1]` | сумма частей = исходной; политика знака остатка фиксируется в spec |
| нулевые ratios | `[0, 0]` | ошибка; `[0, 1]` — нулевая доля не получает остаток |
| округление ничьи | `0.5` minor, HALF_EVEN и HALF_UP | `0` и `1`; режим — явное имя в spec |
| float на входе | JSON number `1.1` вместо строки | отклоняется (REQ-CON-02) |

## Выводы для Billium

1. Ни MoneyPHP, ни Brick Money не задают int64-границу: MoneyPHP хранит строку (DR04-01), Brick — BigDecimal (DR04-05); граница int64 — правило спецификации MoneyWire, проверяемое fixtures (REQ-ACC-13).
2. Exponent валют у обеих библиотек совпадает с ISO 4217 List One на 2026-09-17 (DR04-04, DR04-07, DR04-11); spec Billium фиксирует версию таблицы, а не библиотеку.
3. Allocation MoneyPHP использует float при раздаче остатка (DR04-03) — для largest-remainder (REQ-CON-30) Brick FloorToLargestRemainder (DR04-06) ближе к требованию; выбор — после прогона fixtures (CL-117).
4. Переход CoreX на Brick Money 0.15 меняет API allocate и мажор brick/math (DR04-06, DR04-08, DR04-09): Billium не диктует CoreX апгрейд и не требует общего money-пакета (REQ-OUT-14).
5. Сумма на wire — строка: JCS требует IEEE double для чисел (DR04-12), Dart web теряет точность после 2^53 (DR04-13).
6. JSON обеих PHP-библиотек несовместим: MoneyPHP — minor-строка, Brick — major decimal (DR04-01, DR04-05); MoneyWire требует адаптера в обе стороны.
7. Dart-сторона опирается на `axioma_contracts` (DR04-15); пакет `decimal` (DR04-14) — только если spec потребует rational-операций сверх существующего.
8. Книга vendor billing (Billium, PHP) и книга компании (AiFina, Dart) — разные writers (DR04-16, DR04-19); Billium не реплицирует и не постит в книгу компании.
9. Экспорт в учёт — операционные факты через FinBridge, маппинг у владельца книги (DR04-17, DR04-22); корректировка — новый связанный факт.
10. Durable событие — outbox в той же транзакции (DR04-20); after-commit enqueue (DR04-21) и best-effort callback (DR04-16) не гарантируют доставку.
11. Outbox — очередь, не архив (DR04-23): архив фактов Billium хранится отдельно от очереди публикации.
12. GL в Billium не нужен: obligations/payments/allocations — subledger (DR04-18; REQ-OUT-04).
